> **For agentic workers:** execute with superpowers:subagent-driven-development, one task per fresh subagent + two-stage review. Steps use checkbox syntax. Every finding here was independently CONFIRMED against the v0.22.0 tree by five adversarial validators (see `docs/reports/2026-07-20-v0.22-delta-review.md`); line numbers below are validator-verified.

**Goal:** Fix all confirmed correctness, gate-efficacy, and brand-honesty defects surfaced by the v0.22.0 delta review, plus the cheap housekeeping items it uncovered.

**Architecture:** Fixes span three layers — SQL analyses over the DuckDB fact store (`crates/codelore-lib/src/analyses/`), the change-set gate engine (`change_set.rs` + `quality_gates/`), and the vanilla-JS SPA (`output/spa/`). Each task is one PR-sized commit series with an independently testable deliverable.

**Tech stack:** Rust workspace (edition 2024, rust-version 1.96 — **let-chains ARE stable**), DuckDB (`duckdb` crate, `Connection` !Send+!Sync), gix + git-cli dual backend, vendored ECharts SPA.

**Branch:** `feat/v0.22-delta-fixes` off `main` (ea2d026 = v0.22.0). Ledger: `.superpowers/sdd14/progress.md`.

## Global Constraints (bind every task)

1. `just ci` (fmt-check + clippy `-D warnings` + `cargo deny` + `cargo test --workspace --features test-support,spa`) must pass before every commit. No `#[allow]` to silence lints — fix root cause.
2. No `unwrap()`/`expect()` outside tests. Library errors via `thiserror` (`CodeLoreError`); CLI via `anyhow::Context`.
3. `FactsDb` is READ-ONLY after ingest. Analysis-phase temp writes use prepared `INSERT` / `CREATE TEMP TABLE AS`, never `duckdb::Appender`.
4. **Semantic-preserving SQL refactors must prove byte-identical output** (git baseline → run twice → diff); attach result to the commit. Fixes that intentionally change numbers are NOT byte-identical — they need a corrected-value test instead, and the test's prior expectations must be updated (not deleted).
5. No ticket IDs, version numbers, F-IDs, or static test counts in code/comments/docs. Describe current contract only. CHANGELOG `[Unreleased]` gets one entry per user-visible change. **Never** add `Co-Authored-By: Claude`.
6. Use existing conventions — reuse the exact helper/pattern the codebase already has; never add a second way of doing something. Named sibling patterns are cited per task.
7. Cross-platform CI gotchas: tests that create git commits need `-c user.email=… -c user.name=…`; filesystem paths in TOML must be single-quoted literals. Repo-backend changes must keep both backends byte-identical (a differential test enforces this).
8. Test invocation: `cargo test -p codelore-lib --features test-support,spa <name>`. Run the real CLI to catch the read-only-Appender class: `just codelore -- analyze --analysis <x> --repo . --format markdown`.

### Task 1 — #1 `delivery_metrics` branch-walk stops at merge base (HIGH)

**Files:** `crates/codelore-lib/src/analyses/delivery_metrics.rs` (`BRANCH_COMMITS_CTE`, ~104-155); Test: `crates/codelore-lib/tests/delivery_metrics_test.rs`.

**Defect (CONFIRMED):** the recursive `branch_walk` walks first-parents from the branch tip and stops only when it hits `mainline_parent` (the merge's position-0 parent). Once mainline advances after the branch cut, `mainline_parent` is never on the tip's first-parent chain, so the walk crosses the true merge base and vacuums up to 90 days of mainline history → inflates `batch_size_files`, `batch_size_loc`, and pins `branch_duration_hours` near the 90-day ceiling. Code comments (`:77-83,146-147`) claim an exclusion the impl never delivers.

- [ ] Add a `mainline_reachable` CTE (recursive first-parent walk from `mainline_parent`, same depth/date bounds) and anti-join it out of the branch set — i.e. branch commits = reachable-from-parent1 AND NOT reachable-from-parent0. This yields exactly the commits unique to the branch below the merge base.
- [ ] `delivery_repo` already exercises mainline-advance (v0.2.0 lands Feb between the Jan branch1 merge and Mar branch2 merge). Add/adjust a test asserting branch1's `batch_size_files == 1` (only `src/branch1.rs`) and `branch_duration_hours ≈ 48` (not ~90d), branch2 `≈ 4`. **Update any existing test that currently asserts the inflated values** — do not delete, correct.
- [ ] `just codelore -- analyze --analysis delivery-metrics --repo . --format markdown` sanity. Commit `fix(delivery-metrics): stop branch-walk at the merge base`.
